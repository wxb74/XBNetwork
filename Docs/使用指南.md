# XBNetwork 中文使用指南

本文面向第一次接入组件的 Objective-C 开发者，示例使用公开版本接口。先按 [README](../README.md#安装) 安装，再导入统一头文件：

```objc
#import <XBNetwork/XBNetworkUmbrella.h>
```

## 先理解三个对象

- `XBNetwork`：真正发送请求。类方法使用默认共享实例，自建实例可以配置鉴权、公共参数和日志。
- `XBHTTPRequest`：描述一次请求，例如地址、方法、参数位置、超时和响应类型；创建它不会发送请求。
- `XBHTTPBody`：描述请求体采用表单、JSON、原始数据还是文件上传编码；赋给 `request.body` 使用。

Query 指 URL 中 `?page=1` 这部分，Body 指 HTTP 请求体。服务端要求参数放哪里，就选择对应方法；POST 也可以有 Query。

| 接口要求 | 选择的方法 | 公共参数位置 |
|---|---|---|
| GET 查询 | `GET:parameters:completion:` | Query |
| POST 普通表单 | `POSTForm:parameters:completion:` | Form Body |
| POST JSON 字典 | `POSTJSON:parameters:completion:` | JSON Body |
| POST，URL 带参数且 Body 是 JSON | `POSTQueryJSON:queryParameters:JSONObject:completion:` | Query，JSON 保持独立 |
| POST，URL 带参数且 Body 是表单 | `POSTQueryForm:queryParameters:formParameters:completion:` | Form Body |
| PUT/PATCH/DELETE/HEAD、数组 JSON、原始数据、文件上传或特殊响应 | `sendRequest:...` | 默认不添加，显式选择 |

## 发出第一个请求

```objc
[XBNetwork GET:@"https://example.com/items"
    parameters:@{@"page": @1}
    completion:^(id object, NSError *error) {
        if (error) {
            NSLog(@"%@", XBNetworkErrorDisplayMessage(error, @"加载失败"));
            return;
        }
        // 默认主队列回调。JSON 根对象不保证是字典，按接口检查类型。
        if ([object isKindOfClass:NSDictionary.class]) {
            NSDictionary *result = object;
            // 在这里判断服务端业务状态、读取列表或转换业务模型。
            (void)result;
        }
    }];
```

`example.com` 只是接口占位地址，请替换为自己的服务地址。离线观察真实编码和响应处理可运行仓库 Demo。

组件默认只接受 HTTP 200～299 并解析 JSON，不判断 JSON 中的业务 `code`。`error == nil` 表示 HTTP 与解码规则通过；允许空响应时，`object == nil` 也可以成功。

## 配置自己的网络实例

类方法适合默认行为。需要鉴权、公共参数或独立取消范围时，创建实例并保存到宿主服务或属性中，后续统一通过这个实例请求。

```objc
XBNetworkConfiguration *configuration = [XBNetworkConfiguration new];
configuration.defaultTimeout = 20;
configuration.defaultHeaders = @{@"Accept": @"application/json"};
configuration.commonParametersProvider = ^NSDictionary *(XBHTTPRequest *request) {
    // 每次发送时读取应用当前状态；组件本身不收集设备、用户等信息。
    return @{@"platform": @"ios", @"language": @"zh-CN"};
};
configuration.requestAdapter = ^BOOL(XBHTTPRequest *request, NSError **error) {
    // 此处可从宿主读取当前 Token 并设置 Authorization；不要同步等待刷新 Token。
    NSMutableDictionary *headers = [request.headers mutableCopy];
    headers[@"X-Client"] = @"sample-ios";
    request.headers = headers;
    return YES;
};
XBNetwork *network = [[XBNetwork alloc] initWithConfiguration:configuration];
// 将 network 保存为宿主的 strong 属性，后续使用 [network GET:...] 等实例方法。
```

初始化后修改原 `configuration` 不会更新已有实例。动态 Token、用户切换等值应在 Block 执行时读取；Block 捕获持有网络实例的宿主时，注意使用弱引用。多个线程可以同时发送请求，Provider/Adapter 也可能并发执行，宿主共享状态需自行同步。

发送前处理顺序为：复制请求 → 默认头与单请求头合并 → 公共参数合并 → 适配器 → 编码与启动。Provider 和 Adapter 在发送线程同步执行；完成与进度默认异步回主队列，可用 `completionQueue` 改为串行队列。

适配器返回 `NO` 可拒绝发送。要说明原因，可先判断 `error != NULL`，再为 `*error` 设置 NSError；该错误作为底层原因，包装为 `XBNetworkErrorRequestBuildFailed` 返回。

## 公共参数如何合并

公共参数并非无条件添加。便捷方法按表格自动选择位置，显式请求必须设置 `commonParameterPlacement`：

```objc
XBHTTPRequest *request = [XBHTTPRequest requestWithURLString:@"https://example.com/items"
                                                     method:XBHTTPMethodGET];
request.queryParameters = @{@"language": @"en", @"page": @1};
request.commonParameterPlacement = XBCommonParameterPlacementQuery;
// 对上述配置，最终 Query 包含 platform=ios、language=en、page=1。
[network sendRequest:request completion:^(id object, NSError *error) { }];
```

同名时本次请求字段覆盖公共字段，没有 `userid`/`userId` 特例。Query 和 Body 不跨位置合并；URL 中原有的固定 Query 也不会被动态字典替换，应避免重复配置同名字段。

`Body` 合并位置只支持表单、JSON 字典和 Multipart 普通字段；JSON 数组、Raw 或无 Body 会构建失败。这些接口应选择 `None` 或把公共参数放 Query。

## 完整响应、文本与空响应

需要状态码、响应头或字节时，使用 `detailedCompletion`。例如接口成功返回 UTF-8 文本，且允许 204 空响应：

```objc
XBHTTPRequest *request = [XBHTTPRequest requestWithURLString:@"https://example.com/status"
                                                     method:XBHTTPMethodGET];
request.responseType = XBHTTPResponseTypeString;
request.allowsEmptyResponse = YES;
[network sendRequest:request uploadProgress:nil
 detailedCompletion:^(XBHTTPResponse *response, NSError *error) {
    if (error) {
        NSHTTPURLResponse *HTTP = error.userInfo[XBNetworkErrorResponseKey];
        // HTTP 失败时 response 为 nil；如果已收到协议响应，HTTP 中可读取实际状态码。
        NSLog(@"请求失败，HTTP=%ld", (long)HTTP.statusCode);
        return;
    }
    NSLog(@"成功，HTTP=%ld，耗时=%.3f 秒",
          (long)response.HTTPResponse.statusCode, response.duration);
    // 有字节时为 NSString；允许的空响应则为 nil。
    NSString *text = response.responseObject;
    (void)text;
}];
```

二进制响应选择 `XBHTTPResponseTypeData`；组件会把数据接收到内存，不提供下载落盘或断点续传。HEAD 和 204 不会自动开启空响应许可，需要按接口设置 `allowsEmptyResponse`。

## 上传、进度与超时

```objc
NSData *fileData = [@"示例文件内容" dataUsingEncoding:NSUTF8StringEncoding];
XBHTTPFilePart *part = [XBHTTPFilePart partWithName:@"file"
                                         fileName:@"example.txt"
                                         MIMEType:@"text/plain"
                                             data:fileData];
XBHTTPRequest *request = [XBHTTPRequest requestWithURLString:@"https://example.com/upload"
                                                     method:XBHTTPMethodPOST];
request.body = [XBHTTPBody multipartBodyWithParameters:@{@"folder": @"docs"}
                                           fileParts:@[part]];
request.timeout = 30;       // 系统等待数据超时。
request.totalTimeout = 120; // 整次传输总预算，按接口需求设置。
NSURLSessionTask *task = [network sendRequest:request
                             uploadProgress:^(NSProgress *progress) {
    if (progress.totalUnitCount > 0) {
        NSLog(@"已发送 %.0f%%", progress.fractionCompleted * 100);
    }
} completion:^(id object, NSError *error) {
    // 最终是否成功以完成回调为准，不能以进度 100% 判断。
}];
// 保存 task，用户离开或点击取消时可调用 [task cancel]。
(void)task;
```

文件字段名由服务端协议决定，`fileName` 不会用于读取本地文件。普通上传没有自动的公共参数合并，需要时为请求选择 `Body`。Multipart 的 Content-Type 包含自动生成的 boundary，不要手工覆盖，也不要为了记录日志而读取 `HTTPBodyStream`。

`timeout` 默认沿用实例的 20 秒等待超时；`totalTimeout` 默认不额外限制。列表工厂单独使用 8 秒等待和 10 秒总预算，只在显式使用该工厂时生效。总预算不包含 Provider、Adapter 等发送前工作。

## 取消与错误处理

任务返回时已启动，不需要 `resume`。构建失败可返回 `nil`，但完成回调仍异步执行一次。不要仅因 task 为 nil 就再次展示错误，避免与回调重复处理。

- `[task cancel]`：取消这一个任务。
- `[network cancelAllRequests]`：异步取消该实例的当前任务，实例仍可继续使用。
- `[XBNetwork cancelAllRequests]`：只取消默认共享实例，不影响自建实例。
- `[network invalidateAndCancel]`：永久关闭该实例并取消任务；要继续发送需创建新实例。

已完成的结果无法撤回，取消也不会撤销服务端已处理的操作。页面可以统一判断：

```objc
if (XBNetworkErrorIsCancellation(error)) {
    return; // 主动取消通常无需弹错。
}
if (XBNetworkErrorIsTimeout(error)) {
    // 显示重试入口；是否重试由业务决定。
} else if (XBNetworkErrorIsNotConnected(error)) {
    // 显示网络连接提示。
}
```

结构化错误先用 `[error.domain isEqualToString:XBNetworkErrorDomain]` 判断域，再按 `XBNetworkErrorCode` 分类。请求、HTTP 响应、原始字节和底层错误按可用情况放在 `userInfo`，键及类型见 `XBNetworkError.h`。错误对象保留原始数据，不能直接当作脱敏日志上传。

## 接入日志

配置默认没有日志接收者。实现协议后可选择控制台、文件或自己的调试面板：

```objc
@interface SampleNetworkLogger : NSObject <XBNetworkLogger>
@end

@implementation SampleNetworkLogger
- (void)networkDidRecordEvent:(NSDictionary<NSString *, id> *)event {
    // 回调线程不固定，UI 更新需自行回主队列；文件写入需自行串行化。
    NSLog(@"[%@] %@ %@，错误码=%@", event[@"phase"], event[@"method"],
          event[@"URL"], event[@"errorCode"]);
}
@end

// 创建 XBNetwork 前设置；如只在 Debug 使用，把配置放进 #if DEBUG 中。
configuration.logger = [SampleNetworkLogger new];
```

公开版本事件省略 Body，并脱敏 Query 值和 Header 值，移除 URL 凭据和 Fragment。URL 路径与字段名仍然可见；若它们含业务敏感信息，接收者还需过滤。事件字段和失败时的缺省值见 `XBNetworkLogger.h`，并发请求不应仅按事件先后顺序配对。

组件不自动生成业务调用链或复刻某个 App 的日志格式。Release 是否接入由宿主决定；不要把公开组件事件与宿主自行扩展的日志实现混为一谈。

## 继续阅读源码

公开头文件位于 `XBNetwork/Public`。内部顺序为 `XBNetwork.m`（应用配置）→ `XBHTTPRequestBuilder`（编码）→ `XBNetworkClient`（传输、取消和总超时）→ `XBHTTPResponseParser`（HTTP 校验和解码）。内部头文件不作为接入接口。

本组件未提供自动重试、Token 自动刷新、请求合并、业务数据缓存或证书固定策略；需要这些能力时，由宿主按业务协议实现。
